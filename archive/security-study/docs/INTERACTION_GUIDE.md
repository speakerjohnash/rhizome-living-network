# Presentation interaction guide

## Start and navigation

Open `index.html`. The opening screen includes two links: **Enter the network** and **Read the principles**. The fixed navigation leads to the main technical areas. The scroll-progress indicator shows position in the presentation.

## Engineering lens

The **Engineering lens** button in the top navigation opens an explanatory panel for the chapter in view. It adds implementation notes and specification concepts. It does not change security settings or enable networking.

## Federation

Select **Independent**, **Introduction**, **Approved**, or **Compromised**. The graph changes which community relationships are proposed, accepted, or suspended. Hosting operators, personal vaults, and local agents are shown as separate roles. Community labels can be selected to inspect their responsibility boundaries.

## Protection

Choose **Direct**, **Protected core**, or **Delayed mix**. In protected modes, select **Simulate relay failure** to see the fail-closed behavior. The animated particles represent illustrative traffic paths and are not real network packets.

## Data sovereignty

Write a non-sensitive sample thought and select **Seal locally**. The browser uses AES-256-GCM if the Web Crypto API is available. Select **Unlock locally** to decrypt with the in-memory key. Reset to discard the example state. Do not enter secrets or real personal information while evaluating the presentation.

## Private computation

Use the six visible tabs to compare overlap matching, membership proof, joint statistics, population trends, local inference, and encrypted AI research. The input, computation, and output illustrations update for each selected method. They do not execute those full cryptographic protocols.

## Historical perspective

Select **Then, as known then**, **Now, looking back**, or **Looking ahead**. Adjust the **Evidence cutoff** slider. The graph distinguishes subject time from assessment time. Points and narratives are synthetic, not genuine historical evidence.

## Collective classification

Switch among **Joint view**, **Community A**, and **Community B**. Scrub the year or select **Play history** to animate changing classification distributions. Select legend categories to focus the graph. These are generated example distributions, not measured community voting data.

## Dynamic relationships and mutual consent

Choose **Shared questions**, **Complementary skills**, or **Mentorship**. Select a participant in the scatterplot to inspect a proposed introduction. Select **Preview mutual consent** to reveal two independently simulated approvals. Grant or withdraw either approval. The highlighted relationship changes only when both approvals are present. No invitation, profile, or message leaves the device.

The field and inspector were laid out to keep the consent controls visible together on typical desktop displays. On mobile devices, scroll the visualization horizontally when necessary, and use the inspector below it.

## Resilience and diagnostics

The resilience studio offers **Healthy**, **Partition**, **Stale grant**, and **Forked history** scenarios. Operations are individually marked permitted, blocked, or requiring reconciliation.

The diagnostic graph distinguishes missing evidence, privacy exposure, and bad synthesis. A first observable defect does not necessarily establish a complete causal explanation.

## Hardware and exit

Select **Small node**, **Laptop**, or **Desktop** to review qualitative implementation feasibility. Scores are not benchmarks. The final section summarizes the proposal and opens the technical limitations dialog.

## Display and motion

- Wide screens provide the best overview of dense graphs.
- Small screens use horizontal scrolling for information-rich visualizations.
- The interface responds to the operating system's reduced-motion preference.
- Keyboard focus outlines are supported for navigation controls and many graph nodes.
